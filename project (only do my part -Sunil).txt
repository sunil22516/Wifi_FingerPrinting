Phase-by-Phase Development Plan
Phase 1: Mapping and Data Collection (Do this ASAP)
1. Get the Map: Take a photo of the 4th-floor emergency exit map. Clean it up in an image editor.
2. Establish a Grid: Overlay a 1-meter or 2-meter grid on your map. Give each grid point an X,Y coordinate.
3. Fingerprinting: Member 2 builds a basic app that logs Wi-Fi signals. The team walks to every grid point on the 4th floor, stands still, and records the Wi-Fi signals (RSSI) visible at that exact coordinate into a database (CSV or JSON).
Phase 2: Core Algorithm Development
1. Build the Brain: Take the CSV file collected in Phase 1 and feed it into the KNN algorithm. Test it: If I input these live signals, does the math correctly spit out the X,Y coordinate I am standing on?
2. Build the Graph: Member 3 maps out the nodes. (e.g., Node 1 = Elevator, Node 15 = Room B-412). Write the A* algorithm and test it with dummy start/end points to ensure it draws a logical path.
Phase 3: Frontend Integration
1. Draw the Map: Load the 2D map onto the Android screen.
2. Connect the Engines: Feed the real-time X,Y output from the Localization Engine to the UI so a blue dot appears.
3. Render the Path: Add a dropdown menu for "Select Destination." When B-412 is selected, draw the path outputted by the Navigation Engine over the map.
Phase 4: Field Testing & Tuning (Crucial for Demo)
1. The Reality Check: Take the fully assembled app to the 4th floor. Walk from the elevator to B-412.
2. Tuning: The blue dot will jump around at first. This is where Member 4 adjusts the IMU step-counter to force the dot to move smoothly down the hallway, ignoring weird Wi-Fi bounces.

1. System Architecture
Your application will have three main engines working together behind the scenes.
• The Localization Engine: Scans Wi-Fi RSSI (Signal Strength) and compares it against your pre-recorded "Radio Map" using a K-Nearest Neighbors (KNN) algorithm to find your X/Y coordinates.
• The Navigation Engine: Uses a digital graph of the 4th floor. When the professor asks to go to Room B-412, it runs the A (A-Star) Pathfinding Algorithm* to find the shortest route from the current X/Y to the destination.
• The Sensor Fusion Engine (Optional but highly recommended): Uses the Android phone's Accelerometer and Gyroscope for Pedestrian Dead Reckoning (PDR). This smooths out the user's movement on the map between Wi-Fi scans so the dot doesn't "teleport" wildly.
